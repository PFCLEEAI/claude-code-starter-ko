에이전트, 그림으로 이해하기

3줄 요약
  • 챗봇은 답을 주고, 에이전트는 직접 해요. 파일을 읽고, 고치고, 확인하는 루프를 스스로 돌아요.
  • 모델이 엔진이라면 Claude Code는 차체예요. 여러분이 쓰는 CLAUDE.md, 스킬, 훅, 서브에이전트가 그 차를 내 손에 맞게 튜닝하는 일이에요.
  • 잘 굴리는 비결은 세 가지예요. 컨텍스트를 가볍게, 완료 기준을 분명하게, 위험한 순간엔 사람이 직접 확인하기.

이 장은 수업에서 "에이전트", "하네스", "루프" 같은 말이 나올 때 펼쳐 보는 그림책이에요. 개념마다 그림 하나씩 붙여 뒀으니, 글보다 그림을 먼저 봐도 괜찮아요.

챗봇 vs 에이전트: 답하는 AI와 일하는 AI

Claude.ai 채팅창에 "대구 로컬 브랜드 조사해 줘"라고 하면 답변 글이 돌아와요. 그걸 복사해서 파일로 저장하고 정리하는 건 여러분 몫이에요.

Claude Code에 같은 말을 하면 조금 달라요. 폴더를 살펴보고, 검색하고, brands.md 파일을 직접 만들고, 빠진 게 없는지 다시 읽어 봐요. 결과물이 파일로 남아요.

비유 챗봇은 전화로 레시피를 알려 주는 친구, 에이전트는 우리 집 부엌에 와서 직접 요리하고 간까지 보는 친구예요. 대신 부엌에 들일 땐 어디까지 만져도 되는지 정해 줘야 해요(권한).
🧪 예시

상황: 팀 프로젝트로 대구 로컬 카페 브랜드 5곳을 정리해야 해요.

대구 로컬 카페 브랜드 5곳을 조사해서
이름, 대표 메뉴, 인스타 계정을 표로 만들어 brands.md에 저장해 줘.

결과: 채팅창에서는 표가 담긴 답변 글로 끝나요. Claude Code에서는 학습 폴더에 brands.md 파일이 생기고, 파일을 열면 표가 그대로 들어 있어요.

에이전트 루프: 살펴보고 → 하고 → 확인하고

Claude Code는 일을 끝낼 때까지 세 단계를 계속 반복해요. 공식 문서에서는 이걸 에이전트 루프(agentic loop)라고 불러요.

  1. 컨텍스트 모으기: 파일을 읽고, 검색하고, 무엇을 바꿔야 할지 파악해요.
  2. 행동하기: 파일을 고치고, 명령어를 실행해요.
  3. 결과 확인하기: 잘 됐는지 확인하고, 아니면 1번으로 돌아가 방법을 바꿔요.

실제 예를 볼게요. 학습 폴더에서 이렇게 요청했다고 해요.

✅ 이렇게
notes 폴더에 있는 올리브영 신상품 메모들을 읽고,
카테고리별로 정리한 summary.md를 만들어 줘.
다 만들면 메모 개수와 summary에 들어간 상품 개수가 맞는지 확인해 줘.

Claude는 먼저 notes 폴더 목록을 보고 파일을 읽어요(①). 그다음 summary.md를 써요(②). 마지막으로 개수를 세어 보다가 빠진 상품이 있으면 다시 읽으러 가요(③ → ①). 마지막 문장처럼 확인 방법을 같이 주면 ③단계가 훨씬 정확해져요.

💡 Claude가 엉뚱한 방향으로 가면 Esc를 눌러 멈추세요. 지금까지 한 작업은 남아 있고, 바로 새 지시를 줄 수 있어요.

컨텍스트 관리: 책상을 정리하는 도구 다섯 가지

컨텍스트(context)는 Claude가 지금 보고 있는 책상이에요. 대화, 읽은 파일, 명령 결과가 전부 이 책상에 쌓여요. 책상이 꽉 차면 답이 흐려지고 앞에서 한 지시를 놓치기 쉬워요.

도구하는 일언제
/context지금 컨텍스트를 무엇이 얼마나 차지하는지 색깔 격자로 보여줘요.답이 이상해졌을 때, 먼저 확인용
/compact [지시]지금까지 대화를 요약해서 공간을 비워요. 같은 대화는 이어져요.같은 작업을 계속하는데 대화가 길어졌을 때
/clear빈 컨텍스트로 새 대화를 시작해요. 프로젝트 메모리(CLAUDE.md)는 그대로예요.전혀 다른 작업으로 넘어갈 때
/resume예전 대화로 돌아가요./clear 했는데 이전 대화가 다시 필요할 때
/btw [질문]대화 기록에 남기지 않고 옆길 질문을 해요."아까 그 파일 이름 뭐였지?" 같은 짧은 질문
🧪 예시

상황: 올리브영 상품 기획 대화를 두 시간째 하는 중이에요. 처음에 정한 "가격은 원 단위로 쓰기"를 Claude가 자꾸 잊어요.

/context
/compact 타깃 고객, 고른 상품 3개, 가격 표기 규칙만 남겨 줘

결과: /context 격자를 보면 대화 기록이 칸 대부분을 차지하고 있어요. /compact 뒤에는 긴 대화가 짧은 요약으로 바뀌고, 같은 대화를 가벼운 책상에서 이어 가요.

📌 프로젝트 루트의 CLAUDE.md는 /compact 뒤에도 다시 읽혀요. 대화에서만 말한 지시는 요약 중에 사라질 수 있어요. 계속 지켜야 할 규칙이면 CLAUDE.md에 옮겨 두세요.

하네스(harness): 엔진과 차체

Claude 모델 자체는 글을 읽고 쓰는 능력만 있어요. 파일을 열고, 명령을 실행하고, 권한을 묻고, 대화를 기억하게 해 주는 건 모델을 감싸고 있는 프로그램이에요. 이 바깥 틀을 하네스(harness)라고 불러요. Claude Code가 바로 하네스예요.

비유 모델은 엔진, 하네스는 차체·핸들·브레이크예요. 엔진이 아무리 좋아도 핸들과 브레이크가 없으면 도로에 나갈 수 없어요. 같은 엔진이라도 어떤 차에 얹느냐에 따라 운전감이 달라져요.

하네스 엔지니어링은 이 차를 내 일에 맞게 튜닝하는 걸 말해요. 그림의 '내가 하는 튜닝' 상자에 있는 CLAUDE.md, 스킬, 훅, 서브에이전트처럼 수업에서 배우는 것들이 전부 여기에 들어가요.

🧪 예시

상황: 피치덱 작업을 할 때마다 "답은 한국어로, 파일은 output 폴더에"를 매번 다시 말하고 있어요.

# CLAUDE.md에 한 번만 적어 두기
- 답은 항상 한국어로
- 만든 파일은 output 폴더에 저장

결과: 적어 두기 전엔 매번 같은 말을 붙여야 했어요. 적어 둔 뒤엔 "피치덱 표지 문구 써 줘"만 해도 한국어로 써서 output 폴더에 저장해요. 엔진(모델)은 그대로고 차체(하네스)만 튜닝한 거예요.

워크플로우 vs 에이전트, 그리고 5가지 패턴

Anthropic은 AI로 일을 엮는 방식을 둘로 나눠요. 워크플로우(workflow)는 사람이 미리 정해 둔 길을 따라가요. 에이전트(agent)는 다음에 뭘 할지 모델이 그때그때 정해요.

비유 워크플로우는 정해진 노선을 도는 시내버스, 에이전트는 목적지만 말하면 길을 알아서 고르는 택시예요. 버스는 예측 가능하고, 택시는 유연해요.

정해진 순서로 매번 똑같이 돌아가야 하면 워크플로우가 맞아요(n8n 자동화가 대표적이에요). 무엇을 해야 할지 상황마다 다르면 에이전트가 맞아요. 아래 다섯 패턴은 Anthropic 글 Building effective agents ↗에서 소개한 것들이에요.

패턴한 줄 설명일상 예
① 프롬프트 체이닝(chaining)한 단계의 결과를 다음 단계에 넘겨요. 중간에 검사 관문을 둘 수 있어요.브랜드 조사 → 핵심 메시지 → 인스타 문구
② 라우팅(routing)입력 종류를 먼저 나눈 다음, 각각에 맞는 담당에게 보내요.고객 문의를 상품·배송·불만 창구로 나누기
③ 병렬화(parallelization)서로 상관없는 일을 동시에 돌리고 결과를 합쳐요.동성로·서문시장·앞산을 동시에 조사
④ 오케스트레이터-워커(orchestrator-workers)반장 역할 AI가 일을 쪼개서 나눠 주고 결과를 모아요. 몇 개로 나눌지도 반장이 정해요.신상품 기획을 경쟁사·타깃 고객·가격대로 나눠 맡기기
⑤ 평가자-최적화(evaluator-optimizer)한쪽이 만들고 다른 쪽이 기준에 맞춰 평가해요. 통과할 때까지 반복해요.글쓴이와 편집자가 상세페이지 문구 주고받기

자주 쓰는 ⑤ 평가자-최적화를 그림으로 볼게요. ① 체이닝은 바로 아래 예시로, 나머지는 "패턴 그림 더 보기"에서 볼 수 있어요.

패턴 그림 더 보기
💡 처음부터 복잡하게 짤 필요 없어요. Anthropic도 "가장 단순한 방법부터 시작하고, 필요할 때만 복잡하게"를 권해요.
🧪 예시

상황: 올리브영 신상품 인스타 문구를 만들어요. 한 번에 다 시키지 않고 ① 체이닝처럼 단계를 나눠요.

1단계: 이 상품 설명을 읽고 핵심 메시지 3개만 뽑아 줘.
(메시지를 확인한 뒤)
2단계: 방금 뽑은 메시지 3개로 인스타 문구 2개를 써 줘. 각각 100자 이내로.

결과: 1단계 메시지가 엉뚱하면 거기서 바로 고칠 수 있어요. 내가 확인하는 그 순간이 체이닝의 "검사 관문"이에요.

에이전트 그래프: 누가 누구에게 무엇을 넘기나

여러 단계와 에이전트가 얽히면 머릿속으로 따라가기 어려워요. 그래서 그림으로 그려요. 노드(node)는 한 단계나 한 에이전트, 엣지(edge)는 결과를 넘기는 화살표예요.

수업 후반에 쓰는 n8n은 이 그림처럼 노드를 선으로 잇는 방식이에요.

예시: 작업 흐름을 그래프로 그려 보기

대구 관광 릴스 제작 흐름을 단계(노드)와 화살표로 정리해서

서브에이전트와 병렬 작업

서브에이전트(subagent)는 메인 Claude가 부르는 보조 일꾼이에요. 핵심은 각자 자기 컨텍스트 창을 따로 쓴다는 점이에요. 서브에이전트가 웹페이지 열 개를 읽어도, 메인 대화에는 요약만 돌아와요.

비유 팀장이 인턴 세 명에게 조사를 맡기면, 인턴들은 각자 책상에서 자료를 잔뜩 펼쳐요. 팀장 책상에는 한 장짜리 보고서만 올라와요. 팀장 책상(메인 컨텍스트)이 깨끗하게 유지돼요.
🧪 예시

상황: 관광지 세 곳을 한 번에 조사시키고 싶어요.

서브에이전트를 따로 써서 동성로, 서문시장, 앞산의
관광 포인트를 동시에 조사해 줘. 각자 핵심 5줄만 보고하게 하고,
마지막에 하나의 표로 합쳐 줘.

결과: 서브에이전트 없이 시키면 읽은 웹페이지 내용이 전부 메인 대화에 쌓여요. 서브에이전트를 쓰면 메인 대화에는 보고만 와요.

예시 답변(실제와 다를 수 있어요)

동성로: 쇼핑·카페 거리, 저녁 버스킹 …
서문시장: 야시장 먹거리 …
앞산: 전망대, 케이블카 …

메인 책상이 가벼우니, 이어서 "표로 합쳐 줘"를 해도 앞에서 한 지시를 덜 놓쳐요.

⚠️ 서브에이전트도 각자 요청을 보내기 때문에 사용량 한도에 함께 잡혀요. 서로 의존하지 않는 일을 나눌 때 가장 효과가 좋아요.

서브에이전트처럼 뒤에서 따로 돌아가는 작업(백그라운드 작업)은 /tasks로 볼 수 있어요. 끝난 서브에이전트도 여기 남아요. 직접 서브에이전트를 만들고 싶으면 Claude에게 만들어 달라고 하거나 .claude/agents/ 폴더에 파일을 두면 돼요.

Ralph 루프: 될 때까지 다시 돌리기

Ralph 루프(Ralph Wiggum 기법)는 개발자 Geoffrey Huntley가 2025년에 알린 방법이에요(만화 심슨 가족의 엉뚱하지만 끈질긴 캐릭터 이름에서 따왔어요). 같은 작업 지시를 에이전트에게 몇 번이고 다시 줘요. 매 라운드마다 에이전트는 현재 파일과 결과를 새로 읽고, 완료 기준을 통과할 때까지 이어서 일해요.

이 방법에서 가장 중요한 건 완료 기준이에요. "좋아질 때까지"는 끝이 없어요. "체크리스트 10개 모두 체크", "모든 상품에 가격과 출처 링크가 있음"처럼 눈으로 확인할 수 있어야 루프가 멈춰요.

😕 이렇게 말고
상세페이지 문구 좋아질 때까지 계속 고쳐 줘.

한 번의 요청 안에서도 같은 원리를 쓸 수 있어요.

✅ 이렇게
상세페이지 문구를 고쳐 줘. 아래 4개를 모두 만족하면 끝이야.
1) 200자 이내  2) 성분 이름 2개 이상  3) 과장 표현(최고, 1위) 없음
4) 마지막 문장은 구매 유도. 최대 3번까지만 고치고, 그래도 안 되면 멈추고 알려 줘.
🧪 예시

상황: summary.md의 상품 정보가 군데군데 비어 있어요.

/goal summary.md의 모든 상품에 가격과 출처 링크가 있음

결과: Claude가 빈 칸을 채우고 다시 확인하는 일을 조건이 맞을 때까지 여러 턴 이어 가요. 중간에 멈추고 싶으면 /goal clear를 입력하세요.

📌 같은 프롬프트를 일정 간격으로 반복하고 싶으면 /loop를 써요. 세션이 열려 있는 동안만 돌아요.

인터뷰 스킬: AI가 질문하고 내가 답하기

아이디어가 흐릿할 때 바로 "만들어 줘"라고 하면, AI가 빈칸을 제멋대로 채워요. 그래서 거꾸로 해요. AI가 한 번에 질문 하나씩 던지고, 내가 답하고, 다 모이면 spec.md(기획서)로 정리해요. 이런 흐름을 스킬로 만들어 둔 걸 인터뷰 스킬이라고 해요. grill-me처럼 사람들이 만들어 공유하는 스킬이 있어요. Claude Code에 기본으로 들어 있는 건 아니라서, 없으면 아래 프롬프트를 쓰면 돼요.

✅ 이렇게
지금부터 나를 인터뷰해서 기획서를 같이 만들자.
규칙:
- 질문은 한 번에 하나만 해 줘.
- 질문마다 네가 추천하는 답과 이유를 한 줄로 붙여 줘.
- 목표, 대상 고객, 꼭 필요한 기능, 안 할 것, 완료 기준 순서로 물어봐 줘.
- 내가 "정리해"라고 하면 지금까지 답을 spec.md 파일로 저장해 줘.
주제: (여기에 아이디어 한 줄)

결과: Claude가 "목표가 뭐예요? 추천: 관광객 대상 굿즈 판매"처럼 하나씩 물어봐요. "정리해"라고 하면 학습 폴더에 spec.md가 생기고, 목표·대상·기능·안 할 것·완료 기준이 칸별로 정리돼 있어요.

계획 → 실행 → 검증, 그리고 사람이 끼어드는 지점

큰 작업일수록 바로 실행하지 말고 계획부터 받아 보세요. 플랜 모드(Plan mode)에서는 Claude가 파일을 읽고 조사해서 계획을 쓰지만, 내 파일은 고치지 않아요. 내가 승인해야 실행으로 넘어가요.

  1. 플랜 모드 켜기: Desktop 앱은 보내기 버튼 옆 모드 선택기에서 Plan을 골라요. 프롬프트 앞에 /plan을 붙여도 돼요.
  2. Claude가 계획을 보여 주면 읽어 봐요. 마음에 안 들면 승인하지 말고 고칠 점을 말해요.
  3. 괜찮으면 승인해요. 플랜 모드가 풀리고 실행이 시작돼요.
  4. 끝나면 처음에 정한 완료 기준으로 확인해 달라고 해요.
터미널에서는

Shift+Tab을 눌러 아래 상태 표시줄에 plan mode on이 보일 때까지 바꿔요. 계획이 마음에 안 들면 "No, keep planning"을 고르고 고칠 점을 말하면 돼요.

결과: 고칠 파일 목록과 순서가 계획으로 나와요. 이때는 파일이 하나도 바뀌지 않아요. "표지는 빼 줘"처럼 고칠 점을 말하고, 승인하면 그때 실행돼요.
